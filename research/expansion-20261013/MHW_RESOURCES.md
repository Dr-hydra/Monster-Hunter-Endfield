# 完整 MHW 资源作为扩展素材来源：初查

日期：2026-10-13。此记录是容器结构与工具路线的离线初查，没有全量解包；后续提取与适配进展见 [项目计划](../../docs/PROJECT_PLAN.md)。研究输入与输出仅本地保留。

## 结论

现在的完整《怪物猎人：世界》安装可作为原版武器动作、模型、音效与装配资料的本地提取来源，不必继续仅靠太刀 MOD 包。**本轮验证的是资源容器可读与现有格式工具可用；尚未逐类提取，因此不能写成“14 套原版动画已经全部解码验证”。**

14 类武器可以共用一条人体动作提取与重定向流程。人形骨架应优先按猎人核心 BoneFunction 映射复用，而不是为每类武器复制一套转换器；武器、盾、刀鞘、变形部件、弓弦等另外适配。是否可直接共用当前 104 骨骼的外观 MOD 骨架，必须逐个 LMT 核对，当前只验证过太刀的 68 个非根编号。

## 本轮实际验证

- 本机安装 `<MHW_ROOT>` 的 EXE 与 `chunk/` 可读。
- 13 个 `chunkG*.bin`，共 **54,895,522,591 字节**。13 个包均为 `CMP\0` 头，各自压缩子块表可完整读取。仅检查头和表，不代表整包所有资源已验证或游戏下载完整性已验证。
- 记录见 `mhw_archive_headers.json`。没有解包约 55 GB 的完整数据。
- `<BE_ROOT>/research/actions/mhw-longsword/20261012/tooling` 保留 MHW Anim Tools 与 MHW Model Editor。MOD LMT 可以用纯 Python reader 和 pose-curve 编译器读取。
- 当前 `tools/bake_actions.py` 的源仍为 **Rise Style 太刀 MOD**，骨架仍为 ZXC 外观 MOD 的 `m_body043_0000.mod3`；当前模组并没有因为安装了完整游戏就自动改成原版素材。
- 历史检查记录：Rise 主 LMT 有 164 个非空条目，Valor 有 177 个；解码轨道未报错。这些是 MOD 数据，不是本轮原版全武器检查结果。
- 初查范围内的项目/研究目录没有可用的 WorldChunkTool / MHWNoChunk 程序或 `oo2core_8_win64.dll`，因此原版提取路线尚未执行。

## 提取路线与边界

[WorldChunkTool 作者仓库](https://github.com/mhvuze/WorldChunkTool) 支持世界和冰原 chunk；其 README 明确要求 **`oo2core_8_win64.dll`**，并说明旧基础版的 `oo2core_5_win64.dll` 不适用。其 `-BuildPKG` 会建立包而非直接导出全部文件，仍不应当成低成本的只列目录命令。

[MHWNoChunk 作者仓库](https://github.com/JodoZT/MHWNoChunk) 提供分析目录、筛选与“提取所选文件”。[其 Chunk.cs](https://github.com/JodoZT/MHWNoChunk/blob/master/MHWNoChunk/Chunk.cs) 分开实现目录分析和选取提取，适合后续只取玩家人体、太刀、片手和另外两类武器。无需先全量解包。目录仍在压缩/加密子块中，不能仅靠本轮读到的外层子块表确认武器目录存在。

下一步应联合分析各个 chunk，以其覆盖顺序选择实际生效资源，再选取人体 MOD3、武器装配/模型、对应 LMT、动作逻辑资料与音频库。不能只取 `chunkG0` 后忽略补丁包覆盖。

格式工具已经具备：

- [MHW Anim Tools](https://github.com/wowo-dot/mhw-anim-tools)：LMT/TIML 读取与 MOD3 骨架动作求值；原始曲线正确解码与完整复现游戏控制逻辑是两件事。
- [MHW Model Editor](https://github.com/chikichikibangbang/MHW_Model_Editor)：MOD3 模型、骨架和材质相关导入。
- [vgmstream](https://github.com/vgmstream/vgmstream)：音频转换工具来源；原版各武器 bank/media 本轮未提取或试听。

## 人体共用、武器与控制差异

“共用猎人人体骨架”指核心人体语义与转换流程可以复用，并不表示 14 类武器的全部骨骼、挂点、道具和控制轨道完全一样。当前尚未逐类比对原版 LMT 编号。下表是实施分组的推断，不是已完成的提取清单：

| 武器组 | 人体之外需要处理的内容 |
| --- | --- |
| 太刀、大剑、锤、笛、长枪 | 装配矩阵、握柄、刀鞘/盾、两手关系、招式时序；笛的外形还会影响遮挡 |
| 片手、双刀 | 左手盾/第二把刀、两侧挂点和显隐；终末地只有一件装备模型不足以直接复现 |
| 铳枪、轻弩、重弩 | 盾/枪身/装填部件、枪口、弹药或炮击表现与时序 |
| 斩斧、盾斧 | 形态转换、部件移动与装配、形态之间动作切换 |
| 操虫棍、弓 | 棍与虫/箭/弓弦道具、附属动画、跳跃或瞄准控制 |

FSM/动作配置决定派生、持续时间、输入窗口和状态；动作根/控制轨道影响实际移动与飞行；装配数据决定人体挂点坐标怎样对应武器长轴；特效与音频分别需要自己的资源和时间轴。仅导出当前 21 根人体旋转会丢失手指、部分附属骨骼与控制信息。完整游戏提供这些资料的来源，但需要建立关联才能使用。

## 太刀下劈问题的证据

本轮直接读取当前 Rise MOD：

| LMT 槽位 | 头部帧数 | 曲线最大帧 | 轨道数 | NeedsParent |
| --- | ---: | ---: | ---: | --- |
| 170 | 32 | 106 | 82 | 是 |
| 171 | 1 | 46 | 82 | 否 |

这些轨道均可编译，错误数为 0。当前 README 将它们作为登龙空中/落地素材，历史初始烘焙记录曾跳过 170；当前较新版本已经改为扩展求值。因此不能简单说“动画里没有最后的下劈”。**曲线延伸到 106 也不单独证明怪猎运行时应从 0 到 106 完整播放一次**，还需原版动作配置、控制逻辑和父级基姿上下文佐证。

从现有证据看，先检查动作来源/上下文、源武器装配矩阵、手掌到武器的坐标映射、根与飞行时序，比继续估计剑尖朝向更有依据。README 已明确记录 0.5.5 的估计剑向造成普通动作和插地回归，0.5.6 撤回。完整原版太刀动作与实际武器模型/装配现在是最合适的对照来源；它们尚未提取，因此当前无法断言只有一个具体映射错误。

## 未知项与建议下一步

3. 音频离线解码后进入统一 PCM 链路，不依赖调用游戏音效事件。
4. 在资源提取与对照完成之前，不宣布 14 套武器已适配、不批量修改动作，也不扩大当前模拟伤害/网络逻辑。
