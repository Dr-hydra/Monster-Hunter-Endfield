# Monster Hunter Endfield 项目计划

日期：2026-10-13。项目及后续开发目录：`G:\Monster Hunter Endfield`。本文规定扩展顺序与验收条件，不代表以下功能已完成。

## 1. 目标与当前起点

项目从女管理员太刀演示扩展为“怪物猎人：终末地”：在终末地中提供怪猎式键位、连续招式、自动演示和可选本地练习。人体适配与武器外观分开，同一套动作系统支持不同角色、装备型号和独立展示武器。

旧项目内容已同盘迁移，保留源码、配置、工具、研究资料与本地素材。产品名称先统一为 Monster Hunter Endfield；本轮保留 `endfield.longsword.showcase` 模块 ID、DLL 名和现有配置键，避免迁移导致设置丢失。是否另设新包 ID，在发布兼容方案确定后处理。

当前清单版本为 `0.5.6-dev`，仍是历史开发基线。头文件、`profiles`、音频文件、部分烘焙关联轨道、SDK 与测试文件存在缺项；README 的历史通过记录不能证明当前目录可构建，也不能证明登龙已经还原。先补齐可复现基线，再扩大功能。

已有证据的边界：

- 完整 MHW 的 13 个 chunk 包头及压缩子块表可读，原版各武器尚未提取。现有太刀仍来源于 Rise Style MOD，不能自动视作世界原版动作。
- 32 份角色缓存具备共用的 21 主骨运动链，但绑定姿势、骨长和辅助骨不同；骏卫包含多套同名士兵骨架。缓存兼容不等于全部角色实机认证。
- 莱万汀 `wpn_misc_0016` 与提弗洛斯 `wpn_misc_0051` 确有独立武器模型和自身骨架，具备跨角色展示的结构条件；火焰、拉弦、LOD 和实际加载尚待验证。

证据见 [扩展初查](../research/expansion-20261013/README.md)、[怪猎素材](../research/expansion-20261013/MHW_RESOURCES.md)、[通用适配](../research/expansion-20261013/ENDFIELD_ADAPTATION.md)、[特殊武器](../research/expansion-20261013/SPECIAL_WEAPONS.md)。

## 2. 功能范围

优先完善动作与表现，真实战斗伤害不纳入当前阶段。本地练习维护独立 HP、命中去重和统计；真实怪物最多作为只读目标来源，不改游戏 HP、奖励或存档，不调用攻击、技能或伤害发送接口。后端资料用于理解读取边界，核心功能不依赖启动本地服务器。

“不额外发送战斗数据”作为可验证要求：审查模组调用点，并在本地环境对比演示关闭/开启时的通信。终末地自身的正常联网继续存在，不能承诺整个游戏零数据包。展示位移写显示模型，不把它直接当作真实角色位置；地面、障碍及低顶约束检查不可用时，应显示状态并回退到有限位移。

音效统一从用户本地资源离线提取、解码，经同一 PCM 调度、混音和停止链路播放。普通挥刀可以使用已提取的终末地原声；其余优先怪猎原声。不同来源必须标注，不额外调用游戏音频事件凑效果。

| 终末地类别 | 首批怪猎模式 | 要补的武器表现 |
| --- | --- | --- |
| 单手剑 | 太刀、片手剑 | 刀鞘或左手盾、双手接触 |
| 双手剑 | 大剑 | 握柄、剑轴、蓄力表现 |
| 长柄武器 | 操虫棍 | 棍轴、跳跃、虫的视觉实例 |
| 手铳 | 轻弩 | 双手弩模型、瞄准及装填部件 |
| 施术单元 | 弓候选，待确认 | 独立弓、弦、箭，不能直接套浮游法器 |

类别提供默认推荐，不强制角色永久绑定模式。14 类怪猎武器全覆盖、完整战斗规则和联网共演均不属于本轮承诺。

## 3. 架构与数据职责

沿用 Windows x64、C++20 和 E Mod Loader `format=1 / abi=1`，逐步拆分现有原生模块，不重写为 Unity C# 项目。建议形成七个职责单元，边界稳定后再调整实际文件布局。

| 单元 | 主要职责 |
| --- | --- |
| HostRuntime | EML 接口、运行时方法解析、主线程调度、对象句柄与启停清理 |
| MotionController | 怪猎键位、输入缓冲、招式派生、动作混合、自动演示和时间轴 |
| CharacterRetarget | 以主角色蒙皮确定骨架、读取 bindpose、人体轴映射、骨长与双手 IK |
| WeaponPresentation | 原装备装配关系、独立武器实例、左右握柄、盾/鞘/弦/箭及视觉轨道 |
| StageMotion | 显示位移、地面和低顶检查、脚底接触、镜头跟随与回退 |
| AudioTimeline | 离线 PCM、音量、重叠播放、时间点触发、退出停止 |
| LocalPractice | 只读目标快照、独立碰撞近似、模拟 HP、统计与 UI 状态 |

配置分为三类：武器模式描述动作和派生；角色 profile 只补体型、主骨架路径及确有必要的例外；武器 profile 按资源 ID/形态保存安装矩阵、握柄、长轴和附属部件。共享算法从实际绑定姿势读数，不能复制女管理员矩阵到所有角色，也不能仅凭挂点同名断言所有型号的握持一致。

源素材记录来源版本、补丁覆盖、骨骼映射、动作上下文与装配证据；烘焙输出绑定对应元数据、手部/脚底/武器轨道。缺关联轨道时明确禁用相应功能，不静默套旧数据。角色主骨必须从实际蒙皮 palette 和完整路径识别，排除士兵、分身与武器子骨架。

Unity 对象读写在已确认的主线程进行。宿主集中持有对象引用、输入接管、显示位置、镜头及武器显隐的所有权；禁用、失焦、换人、换模型、场景切换和卸载都走同一清理入口。异步资源结果不能写入已释放对象。

## 4. 实施阶段与验收

### M0：恢复可复现基线

盘点缺项，优先从已存在的源码、合法可复用 SDK 和旧包恢复；不能恢复的部分另行重建并标注。收敛版本号、相对路径、构建与打包脚本，避免依赖旧目录绝对路径。

验收：全新构建目录能生成 DLL、通过实际存在且相关的测试和 EML 导入检查；缺文件不再由历史产物掩盖。记录当前实机问题，不把“构建成功”当作动作验收。

### M1：以原版证据修正太刀

按需提取原版猎人、太刀模型/装配、LMT、动作控制资料和音频，遵循补丁覆盖顺序。先在源猎人上核对完整招式，再重定向到女管理员和“宏愿”。重点检查 NeedsParent 上下文、曲线有效范围、手掌到刀柄关系、起跳和落地时序；视频用于交叉核对，不再凭剑尖应朝下推导手腕。

验收：保留可复现源预览及与用户视频的逐阶段对照；普通斩、纳刀、居合和登龙不出现横拍/插地回归。实机检查后视角下劈、双手握持、平地/坡地/低顶接地、声音种类和触发时机，分别记录未解决的衣物或刀身碰撞。

### M2：通用角色与特殊展示武器

用女管理员、陈千语、男管理员或另一不同体型验证共用算法；莱万汀检验火刀，提弗洛斯检验小体型与弓结构，骏卫专测同名子骨架排除。大潘等特殊体型单列验收，不因骨名齐全直接开放。

火刀先验证刀身和原生材质，再处理环、链和火焰；弓保留自身骨架，再做拉弦和箭。每种普通装备优先沿用原生安装关系，抽查长度与轴向差异，例外才增加武器 profile。

验收：同一动作数据跨体型可播放，换人/换装/禁用能完整恢复；特殊武器无需发动来源角色大招即可显示。未通过的组合在 UI 中标为实验或不可用，不宣称全角色完成。

### M3：片手剑与大剑

每类先选一个参考角色和一把武器，打通源预览、连招和演示，再扩不同体型。片手剑包括左手盾及盾击视觉轨道；大剑包括双手握持、蓄力与落刀表现。沿用统一声音、接地和模拟练习接口。

验收：完整演示与手动派生可连续操作，盾/剑显隐和双手接触可核对，取消与退出无残留；新增模式不破坏太刀。

### M4：长柄、手铳与施术单元方案

依次验证操虫棍和轻弩。弓模式在源动作、模型与拉弦能力验证后决定是否作为施术单元默认推荐；虫、箭和弹道先为纯视觉对象。未有素材证据的招式不以相似片段代替后宣称还原。

验收：各已承诺装备类别至少有一个完整、可实机验证的动作模式；附属部件、瞄准、跳跃和声音都有明确生命周期，练习仍只操作独立模拟状态。

### M5：整合与发布

整理模式选择、推荐适配、键位、音量、展示位移和练习设置；建立版本兼容表及问题复现材料。执行离线回归、EML 包验证和实际游戏验收，检查新加载资源是否会影响原装备恢复或新增战斗通信。

验收：发布包可重复生成，明确支持角色/武器/客户端版本，所有失败路径可退出。未实测的组合保留标识；历史测试、源码测试和实机结果分开报告。

## 5. 仓库与工作方式

目标远端为私有 `Dr-hydra/Monster-Hunter-Endfield`。Git 只收源码、文档、配置模板和必要的小型元数据；原游戏资源、外观 MOD、解码音频、模型、烘焙素材及大型研究输出在本机保留，不随首个提交上传。构建缓存、ZIP/DLL、账号与凭据也不入库。后续分享方式单独处理。

开发和产物均放 G 盘。先建立清晰 `.gitignore` 与本地路径配置，逐步消除旧目录引用。每阶段保留最小复现输入说明、结果和未通过项，默认不计算产物哈希。验证采用已有有效测试、必要的坐标/生命周期回归与直接文件比对；没有新增风险时不重复扩大测试。

## 6. 主要风险与待定项

原版动作上下文、源武器装配及提取工具依赖是太刀还原的首要风险；运行时骨架选择、比例、指骨和衣物决定通用化上限；火刀/弓的 shader、VFX、LOD 与异步卸载需要实机验证。显示位移的地面近似不等于完整场景碰撞，必须明确回退状态。

尚待讨论：施术单元是否默认映射弓、首批正式支持角色、独立展示武器与原装备的选择入口、新包 ID 与配置迁移、可分享素材的交付方式。计划按验收推进，不提前承诺工期或把资料存在等同功能完成。
