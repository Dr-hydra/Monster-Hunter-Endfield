## 1. 成品范围

成品通过 E Mod Loader 安装，用户选择角色、怪猎模式和展示武器后，可以按怪猎默认键位连续操作、播放完整演示，或开启本地练习。动作、握持、显示位移、特效、声音与 UI 共用状态和时间轴，切换和退出可以完整恢复。

动作及操作以 **《世界／冰原》原版**为基准。旧 Rise/Valor MOD 条目保留明确来源，不混入原版还原验收。1.0 覆盖终末地五类装备、六个怪猎模式、支持版本内的全部角色和两把重点特殊武器。

| 终末地类别 | 成品默认模式 | 装备与道具方案 |
| --- | --- | --- |
| 单手剑 | 太刀、片手剑 | 原装备逐型号校准；太刀补收纳/刀鞘，片手剑补左手盾，可用独立模型 |
| 双手剑 | 大剑 | 双手柄位、剑轴、刃面、尺寸与蓄力接触校准 |
| 长柄武器 | **长枪** | 枪尖突刺、防御、反击、后撤、冲锋；补左手盾，按长枪握持设计 |
| 手铳 | 轻弩 | 优先独立弩模型完成托手、枪口和装填；原手铳只开放外形/握持成立的组合 |
| 施术单元 | 弓展示模式 | 提夫罗斯弓或其他已验证独立弓，原施术器按原状态隐藏/恢复 |

类别是默认推荐；最终全部角色均可借助独立展示模型使用六模式。先完成各角色默认类别，再完成跨类别矩阵。普通装备适用模式、独立模型替代、原显隐恢复分别记录，不要求把所有 80 件原装备硬套六种动作。

莱万汀＋太刀＋`wpn_misc_0016` 火刀、提夫罗斯＋弓＋`wpn_misc_0051` 为两个 P0 精修组合；完成原角色表现后，两把武器仍须跨角色通用。操虫棍、铳枪等其他怪猎模式可在 1.0 后另开扩展，不能替代本期长枪。

真实怪物伤害、掉落、任务结算和联网共演不属于 1.0。格挡、见切成功、资源槽和命中反馈用于本地练习，不赋予真实无敌或真实战斗收益。核心功能不依赖本地服务端。

## 3. 资源和验证以离线为主

**角色材料优先使用 BE 资源导出器。** 查骨架、挂点、模型、材质、动作和音效无需先开游戏。按当前有效 VFS 覆盖读取；旧缓存版本不符时定向刷新，避免全量重复解包。

| 已有工具（BE 路径相对 `G:\Better Endfield`） | 用途 |
| --- | --- |
| `tools/CustomModel/extract_native_bundles.py` | 定向提角色 world/UI、武器 prefab 与依赖闭包；独立武器支持 `--asset-only --extra-asset` |
| `toolchains/native-asset-reader/identities/NativeAssetReader.dll` | 读取对象图、网格/蒙皮、主骨架、bindpose、材质/纹理引用 |
| `tools/CustomModel/parse_native_models.py` | 解析路径、palette、LOD、依赖与缺失项 |
| `tools/CustomModel/NativeAssetReader/` | 源码与 TypeTree 字段依据，核对矩阵布局 |
| `toolchains/EndfieldUnpacker/AnimeStudio-net10/AnimeStudio.CLI.exe` | 支持对象的网格、纹理和元数据导出；自定义 ACL/shader 单独验证 |
| `scripts/GenerateResourceManifests.py`、EndfieldUnpacker、vgmstream | Event/Bank/HIRC/Media 关系与原声音频解码，沿用禁用非必要产物哈希的调用方式 |

本项目复用 `tools/mhw_extract_original.py` 的补丁合并/定向提取，扩展 `mhw_bake_original.py` / `mhw_publish_baseline.py` 的太刀求值与发布流程；音频复用 `mhw_bake_audio.py`、`endfield_extract_swings.py`、`merge_endfield_swings.py`。当前脚本有太刀/三条普通斩专用部分，需泛化，不能写成已支持全武器。

默认流程：**有效索引 → 定向导出 → 依赖/坐标审计 → 源猎人＋源武器复现 → 目标角色带网格预览 → 烘焙 → EML 离线验证 → 必要运行抽验**。Blender 后台优先使用项目 `local/tools/blender`。工具路径配置化，按版本和来源可重建。

派生资源记录游戏版本/manifest、源路径/ID、覆盖来源、工具版本、骨骼映射、槽/帧范围、附属轨道及未知项。单位、坐标系、矩阵布局、mesh→bone→prefab→hand 分层记录。默认不计算产物哈希，使用清单、尺寸及必要的直接文件比较。

离线预览必须含实际角色网格、手指和实际武器，不能只有 21 骨线条。重点招式输出前/后/侧视角、慢放、关键帧和声音，叠加掌心、柄位、刃面/枪尖/箭轴、脚底及根轨迹。穿插扫描定位异常帧，人工复核；近似碰撞不是完整衣物物理。特殊 ACL 转换需核对真实轨道和逐帧姿态，生成 FBX 文件但零轨道不能算导出成功。

原生 shader/VFX 最终外观、布料/链条动态、运行时挂载、场景碰撞、换人/换装恢复、实际 HUD 遮挡与通信边界保留末端运行检查。日常修改不依赖每次进游戏。证据等级和支持版本写入 [覆盖表](ADAPTATION_COVERAGE.md)。

## 4. 通用适配和重点专项

### 4.1 共用系统，分别保存差异

32 份对象图拥有同样的 21 主骨祖先拓扑、掌指根及基础挂点，但序列化姿势有 24 组、臂长有 7 组。共用 bindpose 求值、语义映射和骨长适应；不能复制女管理员矩阵，也不能只按身高缩放。

| 层 | 共用职责 | 差异配置 |
| --- | --- | --- |
| 武器模式 | 输入、派生/状态机、动作/事件时间轴、自动演示 | 各模式招式、瞄准/蓄力/防御、道具与声音 |
| 人体 | 主蒙皮识别、姿势转换、身体轴、骨长、手脚约束 | 体型预设；角色根路径、手指/肩肘、体积和服装例外 |
| 武器模型 | 自身骨架/蒙皮、实例生命周期、握柄与附属驱动 | 资源 ID＋形态：安装矩阵、主轴/刃面、双手、盾/鞘/弦/箭/枪口 |
| 角色表现 | 原装备显隐/恢复、模式切换 | 分身/士兵隔离、专属外形、多武器实例 |

同名挂点可共用定位接口，不证明安装矩阵相同。剑轴由 mesh、真实 bindpose 与武器骨架求值，不能直接从 renderer 偏移或包围盒猜。主人体以实际 SMR palette 和完整路径选取，排除骏卫的四套士兵骨架及武器子骨架。

当前名单基准为 **33 个角色配置（含男女管理员）、80 件装备记录**；名单、ID 与缺口见覆盖表。发布前按支持客户端重新生成清单，新角色进入待办，不默认为已认证。

### 4.2 动作、握持与接地

- 源猎人先核对槽位、父级上下文、有效帧范围和控制轨道，再重定向；六模式均建核心招式清单和派生图。相似片段不能冒充招牌动作。
- 掌心到柄、左手支持、包握手指、肩肘扭转和刃面一起校准；IK 用于有依据的接触，不根据“刀尖应该朝下”改源手腕。专项修复回归普通招式。
- 地面动作维持脚底接触；空中姿态、显示根轨迹、落地约束分别管理。平地/坡面/台阶/边缘/墙/低顶/镜头分别验收；约束不可用时显示原因并有限位移。
- 显示位移不写真实实体位置；演示循环按局部基准接续/复位，不累积飘走。明显持续悬空、卡地下、落地失败阻挡成品发布。
- 键位按 MHW 世界/冰原近战和远程默认分别核对，支持重绑定、组合键、按住/松开、输入缓冲和手动接管；各模式有动作与派生提示。

### 4.3 莱万汀太刀：P0

从 view-part、武器装配和技能表现配置补齐当前 `wep_R` 安装候选的作者依据。先验证普通斩、突刺、全部气刃、见切、特殊纳刀、居合、登龙。登龙逐阶段检查起手、起跳、举刀、下劈、落地，保留后/侧视角对比；原安装/下降未确认时保留实验标记，不用猜测角度掩盖。

完整火刀保留原材质、刀/环/38 骨 VFX 子骨架，接入环、链和火焰的生成/持续/消失，提供完整与简化特效档。由纯视觉时间轴驱动，不释放来源角色大招；刀骨不改绑成人体骨。收纳使用有依据的鞘或独立收纳表现，没有匹配鞘时不硬套会穿模的通用鞘。

精修同时完成太刀与火焰声音，推广到女管理员、男性、小体型和大潘样本，再覆盖所有角色。保证跨角色使用而非仅原角色专属。

### 4.4 提夫罗斯弓：P0，与太刀并行

从 `wpn_misc_0051` 的 9 骨弓身、3 骨弦确认握弓点、拉弦指、弦中心/上下端、箭搭点、出箭轴；不同 LOD 按各自路径/骨名映射，不能照搬数字 palette。优先解决短前臂比例、肩肘和拉弦距离，再推广不同体型。

完成取弓、持弓、瞄准、蓄力、连射、刚射、滑步派生、龙之矢、取消、收弓，其他原版核心招式按清单推进。原生弓臂/弦变形、箭生成/释放/回收、蓄力亮度和本地飞行/命中特效与声音同步；弦的溶解/流动材质单独处理，不能仅做拉手动画。原施术器可恢复，箭弹只做本地视觉/练习。

## 5. 各模式完整音效

音效随动作一起开发。怪猎模式优先 MHW 原声，终末地特殊武器火焰/弓弦及合适的普通挥刀从本地客户端提取；全部走统一 PCM，不另调游戏声音事件。现有太刀标签有部分来自用户对照表，cue 为演示编排，后续须补事件条件/原生时序证据。

**其他五模式已有原版音效资源入口，不限于太刀。** 2026-10-14 只读核对本地 `research/mhw-original/merged-index.json`，以下路径在 `sound/wwise/Windows/` 下均有非零大小条目，当前生效来源为 `chunkG0.bin`。这证明可以开始定向提取，尚不代表已经解码、补齐外部媒体或确认所有招式用途。

| 类别 | 覆盖内容 |

| 太刀/火刀 | 各气刃、见切、居合、登龙起跳/下劈/落地、火焰启动/循环/停止 |
| 片手/大剑/长枪 | 盾击/盾碰、蓄力阶段/释放、重斩、枪刺、冲锋/急停、模拟防御/反击 |

建立 `源事件→Bank/HIRC/随机或序列容器→Media及条件/变体→PCM→动作标记或本地事件 cue` 表，保存来源版本/语言、用途依据、时长、音量、触发相位和未知项；不取首个 Media 代替整个事件。未知用途先试听，缺声列待补，不静默换成无关素材。

统一链路从单次 cue 扩展到循环 start/loop/release/cancel/stop、分组淡入淡出、变体/去重、优先级/并发限流、声像/距离、分类音量、设备失败回退。声音按动作时钟触发，变速默认不改变音高；暂停/快进/静音恢复不补播过期 cue。按模式增量构建，重新烘焙一类不能覆盖其他已合并音源。

空挥和模拟命中分离，见切/格挡成功声须有本地判定或明确的演示事件。一键成功演示可编排模拟事件并标明。人体喊声作为独立可选项，不默认强加怪猎语音。

每模式有全部承诺招式的覆盖表、试听、音画合成预览及实际触发清单；核对峰值/空白/截断/循环接缝和火焰叠加音量，验证两轮演示确实出现不同声音。重播、取消、静音、变速、换人、卸载和设备失败均不能残留或积压补播。

## 6. 游戏内 UI 与网页设置端

这两部分作为正式工作包，详见 [界面与交互计划](UI_DESIGN_PLAN.md)。目标是游戏中信息清楚、不遮挡，网页中设置可理解、可预览、能确认已生效，并具有一致的视觉设计。

| 界面 | 成品职责 |
| --- | --- |
| 游戏 HUD | 模式/当前招式、可派生键提示、本地资源槽、瞄准/蓄力、练习目标与模拟反馈、状态/退出提示 |
| 演示/摄影 | 序列选择、进度/暂停/慢放/循环、手动接管；一键隐藏 HUD，可缩放/定位并适配宽屏 |
| 外部网页 | 概览、模式/角色/展示武器、动作与演示、键位、音效/特效、HUD/练习、预设和诊断 |
| 首次使用 | 资源/宿主状态、推荐组合、一键演示、默认键位、退出方式；复杂校准放高级设置 |
| 配置与反馈 | 单一运行状态来源，保存/应用/未连接状态可区分；预设、恢复默认、冲突提示、失败可重试 |

游戏 HUD 只展示模组掌控的本地状态；模拟 HP/伤害不冒充真实怪物数据，不改游戏原菜单和服务器战斗 UI。键鼠焦点和输入捕获要明确，网页操作不误触游戏连招，HUD 拖动/编辑不影响退出热键。

建立统一色彩、字体、间距、图标、按钮/状态和动效规则，两个重点武器允许主题点缀，信息结构一致。适配小窗口、缩放、高 DPI、键盘导航和非纯颜色状态提示；普通设置有合理默认、清楚说明和即时预览。无需为日常开关增加确认弹窗，仅对覆盖/删除用户预设等破坏性操作提供保护。

先做信息结构与静态交互原型，再接真实宿主状态。网页用真实浏览器验收断连、加载、失败、保存/重载、键位冲突及预览；游戏 HUD 先用离线状态回放验布局/时序，再集中检查实际画面遮挡与输入。UI 不能把未验证组合显示成“完美适配”。

## 7. 工程与本地练习边界

继续 Windows x64、C++20、EML format 1 / ABI 1。模块 ID 暂留 `endfield.longsword.showcase`；若正式命名迁移，必须提供旧配置转换和包冲突处理。

职责分为宿主/生命周期、模式输入/状态机、重定向、武器/特效、地面/镜头、音频、本地练习、配置/UI。先建立共用接口，避免每角色复制播放器；资源按需加载、缓存有界，异步不阻塞帧循环，Unity 对象在确认主线程读写。

练习用独立 HP、命中去重、武器/箭弹轨迹、资源槽和统计；可自建目标，真实怪物仅提供只读位置/外形近似。真实 HP、位置、AI、受击、奖励、存档与服务端均不写，模拟反馈为独立显示。要求是**模组不新增战斗发包/服务端写入调用**，游戏自身正常通信仍存在；静态调用审查和本地对照验证分别留证。

退出、游戏内 Esc、失焦、换人、换装/换模型、切场景与卸载使用统一清理：释放输入，停声音/特效，回收箭弹/展示部件与句柄，恢复原武器、显示位置和镜头。异步结果不得复活旧对象；加载失败能恢复控制。

用户主动暂停用于摄影/逐帧：冻结动作、显示位移与效果，停止声音，保留播放位置和有效资源；恢复前重新核对角色/模型/资源身份，只恢复当前应有的持续声，不补播过期 cue。身份失效则完整退出。网页捕获按键或弹层中的 Esc 只取消当前编辑，游戏内 Esc 保留退出；HUD 编辑退出后也不能吞掉后续游戏退出键。

**1.0 完成标准：**

1. 六模式有可追溯的核心招式/派生清单、默认键位、手动操作和覆盖核心段落的演示；依赖外部机制的边界明示，不以替身动作冒充。
2. 支持版本的全部角色通过六模式离线带网格检查；普通装备和两特殊武器按覆盖表完成，小体型/大潘/骏卫等有专项证据。
3. 莱万汀火刀、提夫罗斯弓原角色精修与跨角色使用完成，刀焰/环链、拉弦/箭、LOD 和对应声音正确，普通装备可恢复。
4. 握持、刃面/枪尖/箭轴有源依据；重点连招无明显手臂/武器穿身体回归，脚不持续悬空/穿地，空中轨迹可落地；衣物物理限制独立记录。
5. 承诺声音清单闭合，循环/一次性混音和条件 cue 正确；静音、变速、取消、失焦和结束无残留，设备失败不锁控制。
6. 游戏 HUD 清楚可定制/隐藏，网页导航、默认值、预览、预设、冲突/错误反馈和状态同步完成；小窗口、高 DPI、键盘操作及真实宿主往返通过。
7. 离线、宿主和实际运行证据分别记录。代表体型、挂载/材质/LOD 分支与场景的末端检查通过；未亲自实测的组合不伪称逐项实测。
8. 在记录硬件/客户端上测帧耗时、加载峰值、内存及音频/箭弹并发，建立并达到预算；长时间循环/切模式无持续资源增长，失败可退出恢复。
9. 无新增真实战斗伤害/服务端写入/战斗发送调用。干净 EML 库安装、升级、禁用、卸载可重现，配置迁移与文档/包版本一致。

错误剑向、登龙横拍/插地、拉弦错位、持续悬空/穿地、失去控制、声音无法停止、资源泄漏、重要配置丢失或新增真实战斗调用均阻挡正式发布。不能把未完成全覆盖整体标成“实验”后宣称成品。
