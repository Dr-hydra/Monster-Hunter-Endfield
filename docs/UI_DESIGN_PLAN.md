# Monster Hunter Endfield 界面与交互成品计划

日期：2026-10-14。开发目录：`G:/Monster Hunter Endfield`。
本文是最终成品的设计与验收计划，不表示目标界面已经实现；总范围以 [PROJECT_PLAN.md](PROJECT_PLAN.md) 为准。

## 1. 已有界面与缺口

- `ui/index.html`、`app.js`、`style.css` 已提供太刀单页：状态、演示控制、设置、源骨骼预览、四类音效试听、键位和本地练习信息。
- 当前配置页通过 EML WebBridge 读取/保存配置及发送请求；直接打开时使用浏览器本地存储，二者尚无完整的冲突与迁移流程。
- 当前状态能展示角色、动作槽、武器、最近音效、声音触发数及地面处理情况；尚无多武器导航和完整兼容矩阵。
- 当前试听直接播放 WAV，提示原文件音量与运行时平衡音量有差异；成品应提供可比较的同一处理结果。
- `native/practice_hud.h` 已有点击穿透、无焦点的 Windows 练习文字浮层，随本进程前台窗口显示并在退出时清理。
- 当前 HUD 固定约 370×136、左上偏移和字号；尚无武器资源条、准星、派生提示、布局编辑器或摄影隐藏功能。
- 既有浏览器及离线宿主验证仅证明既有功能；下文新增项目均需另行验收。

## 2. 产品原则与职责

- 游戏内回答“我在什么模式、下一步能做什么、操作有没有成功”；网页负责配置、选型、预览和排查。
- 常用入口保持简洁；素材编号、骨架路径、资源诊断和详细日志收在高级检查页面。
- 模式系统沿用原生 C++ / EML；网页不成为另一套连招、命中或资源槽运算系统。
- 所有练习 HP、伤害、资源槽和提示来自本地模拟，界面不得暗示已经改变怪物真实血量或战斗规则。
- 不增加联网共演或真实伤害入口；音效素材离线提取后使用统一 PCM 处理和播放链路。
- 普通切换、保存、试听和演示无需额外确认；仅覆盖或删除已有用户预设时确认。

## 3. 游戏内 HUD 信息层级

| 层级 | 默认内容 | 显示规则 |
| --- | --- | --- |
| 常驻摘要 | 模式图标/名称、手动或自动、退出快捷键 | 演示激活时显示，保持单行或紧凑两行 |
| 操作核心 | 当前招式、可用派生与实际按键、蓄力/资源状态 | 只列当前状态可执行的动作，初学提示可关闭 |
| 目标反馈 | 当前练习目标、模拟 HP、模拟命中/伤害 | 仅本地练习开启且目标有效时显示 |
| 短时反馈 | 输入已缓存、不能派生的简短原因、动作完成 | 合并重复消息，不遮挡角色或准星 |
| 诊断 | 资源缺失、接地回退、装配检查结果 | 默认仅保留影响当前操作的一条，细节在网页 |

- 当前招式用中文名称；槽位号仅在调试模式出现，不能让玩家根据编号判断招式。
- 派生提示显示“招式＋键位”，区分立即可用、已缓存、等待窗口，避免颜色成为唯一信息。
- 太刀气刃、大剑蓄力、长枪防御/反击、弩弹药及弓蓄力按实际实现选择组件；未实现的规则不显示假进度。
- 资源条标为“本地”，初次查看说明其只服务展示/练习；不复用终末地官方能量槽造成误读。
- 长枪布局以枪盾、突刺和反击为核心，不出现虫槽或操虫提示。
- 弓/轻弩瞄准时才显示准星及蓄力/装填环；缺少可验证的射线或目标时不能显示“命中”状态。
- 模拟目标面板固定写“模拟 HP”，跳字写“模拟”；归零显示“练习完成”，不写真实击杀或掉落。
- 目标离开、销毁、换场景时及时清理或标为失去目标，避免保留在错误角色或对象上。
- 自动演示可显示当前章节和下一章节；手动接管后立即切换状态，不持续播放下一段提示。
- 见切成功声/反馈在自动演示中标明为编排；练习模式仅依据本地模拟判定触发。

## 4. HUD 布局、摄影与操作

- 默认将状态放左上安全区、派生提示放下方侧边、练习目标放可选侧栏；中心优先留给角色与瞄准。
- 使用游戏客户区和 DPI 计算布局，不继续依赖固定窗口边框偏移；支持 16:9、16:10、21:9 和窗口缩放。
- HUD 缩放先提供 75%–200%，边距提供统一安全区；拖动位置以归一化锚点保存，分辨率变化后收回可视区。
- 提供“精简、教学、摄影”布局预设；摄影隐藏模组 HUD 和提示，网页始终保留结束演示入口。
- 布局编辑是显式进入/退出的独立状态；运行时点击穿透，编辑时才允许拖动，不永久抢占游戏鼠标。
- 开始编辑时停止接收战斗展示输入，退出后恢复；失焦、换人、卸载时统一解除输入和浮层占用。
- 用户可逐项关闭派生、跳字、目标面板及装饰；保存布局与“恢复默认布局”分开，不重置键位或音量。
- HUD 可见性、位置和内容更新分离；重复相同状态不重绘，动画关闭时仍能读懂反馈。

## 5. 外部网页的信息结构

| 页面 | 主要任务 | 首要操作 |
| --- | --- | --- |
| 开始 | 查看连接、当前角色/模式、最近预设 | 开始手动、自动演示、结束 |
| 角色与武器 | 选择模式、装备或独立展示武器、查看适配状态 | 应用推荐组合、查看限制 |
| 动作与键位 | 查看完整招式、派生、组合键、输入缓存 | 试演、改键、恢复当前模式默认 |
| 声音与表现 | 音量分组、音效试听、位移/附属物、HUD 主题与布局 | 试听、预览布局、保存 |
| 本地练习 | 目标选择、模拟参数和统计 | 开始/结束练习、重置本地统计 |
| 预设 | 命名、复制、导入、导出、版本兼容 | 应用、另存为 |
| 检查与帮助 | 支持矩阵、资源诊断、版本信息、复现导出 | 检查资源、复制诊断摘要 |

- 桌面采用稳定侧栏，窄窗口改顶部选择器；所有页面保留连接状态和“结束”按钮。
- 不把长篇工程说明放在首页；用户遇到限制时，在对应项目旁给出具体原因和可行操作。
- 使用“尚未验证、实验可用、已验证、不支持”状态及文字说明，另标资源版本；离线通过不能自动升级为实机已验证。
- 角色列表可按武器类别、支持模式、适配状态筛选；具体型号的握柄例外与角色体型问题分别展示。
- 推荐组合优先莱万汀太刀、提夫罗斯弓；通用组合与重点优化组合共享入口，不需要玩家理解内部 profile。
- 非当前游戏角色可离线查看和编辑配置，但明确“正在预览”；应用到当前角色需通过宿主确认身份。
- 两个特殊武器作为独立展示选项，列明刀身/火焰/环链或弓身/弦/箭的实际支持状态。

## 6. 首次使用与日常流程

1. 首次打开检查 EML 桥接、资源清单和配置版本；未连接仍可浏览、试听和查看离线预览。
2. 已连接时读取当前角色/装备并给推荐模式；未连接时允许选研究角色，不假装已检测到游戏对象。
3. 展示当前模式的核心键位、结束键和“自动演示”入口；默认不强制完成教程或播放整段演示。
4. 提供短段动作预览与完整演示两种选择，先让用户确认角色、武器和声音，再自行开启本地练习。
5. 保存最近使用组合，之后直接进入状态首页；新功能提示只出现一次，并可在帮助里重看。

- 改键同时显示单键、组合键、长按与模式作用域；检测模组内部冲突和已知游戏默认冲突。
- 无法读取用户游戏键位时标记“游戏键位未核对”，不能声称无冲突；提供替代键方案而非强制覆盖。
- 键位捕获期间只处理本次输入；Esc 取消捕获，不因此触发模组演示动作。
- Esc 按焦点分配：网页捕获/弹层仅取消当前编辑，游戏内保留结束演示；HUD 编辑提供明确退出入口，结束编辑后恢复游戏退出热键。用户暂停保留播放位置，继续前校验当前角色/资源，不补播已过期音效。
- 每个设置显示单位、允许范围和默认值；高级校正折叠，避免初次使用要求手调握柄矩阵。
- 动作预览可选择源猎人/目标角色、前后侧视角、速度、逐帧和关键阶段；清楚标出离线预览与实验组合。
- 普通用户主要看完整模型、刀柄接触和脚底；骨架、坐标轴、源帧对照作为检查层按需开启。
- 同一动作可以绑定离线 PCM 试听，附来源与用途置信度；未知音源保留待定，不按编号伪造用途。

## 7. 配置与状态一致性

- 原生宿主是游戏运行状态唯一来源；页面只提交意图，不先把按钮点击渲染成动作执行成功。
- 区分“编辑未保存、已保存、等待应用、已应用、应用失败”；即时音量预览也应标明临时状态。
- 请求带标识，宿主回报结果和状态版本；超时显示可重试，不因轮询或重连重复开始动作。
- 配置分全局、武器模式、角色例外、武器型号和用户预设；继承来源可查看，覆盖值可单项复位。
- 使用版本化配置和原子保存；无效值保留上次有效配置并定位字段，迁移失败不清空用户设置。
- 独立浏览器本地配置是离线草稿；连接后先读取宿主，提供“应用草稿”入口，不自动覆盖宿主配置。
- 网页多窗口通过宿主版本核对冲突，保留尚未保存字段；重连后不会拿过期草稿覆盖新配置。
- 预设导入先校验结构、模式依赖和版本；缺失素材说明受影响项，允许保留其余可用设置。
- 普通另存预设直接完成；覆盖同名预设或删除时才确认，并明确受影响名称。
- 声音页面和 HUD 使用同一音量/静音状态；网页试听用同一解码及音量处理规则的产物，避免两套听感。

## 8. 失败与空状态

| 状态 | 页面行为 | 恢复入口 |
| --- | --- | --- |
| EML 未连接 | 保留离线功能，游戏执行按钮解释不可用原因 | 刷新连接、打开使用说明 |
| 模块已连但角色未就绪 | 显示等待角色，不套用上一个对象 | 自动刷新、结束 |
| 模型/音源缺失或加载失败 | 标明受影响组合或声音层；独立功能继续可用 | 检查本地资源、重新加载 |
| 武器组合未适配 | 保留资料与预览，不把禁用按钮做成无解释灰块 | 选择已支持组合 |
| 配置保存成功但应用失败 | 保留已保存状态并给出失败原因 | 重试应用、恢复上次有效值 |
| 地面/对象状态失效 | 显示回退或已停止，清除过时目标 | 回到可用场景后重新开始 |

日志默认给简短可读结论；详细诊断只在检查页展开，导出不包含账号、令牌、完整私人路径或原始游戏素材。

## 9. 视觉规格与可访问性

- 设计 token 统一管理：背景 `#111715`、面板 `#1B2420`、主文本 `#F2F5EE`、次文本 `#B8C3BA`、描边 `#43534A`；实施时逐项检测对比度。
- 基础强调色 `#CDEB94`；莱万汀主题采用暖铜/橙，提夫罗斯弓主题采用冷青，作为产品主题，不宣称复刻未提取的官方 UI。
- 两主题仅改变强调色、图案和武器标识；确认/失败/模拟标识的语义颜色固定，模式切换不改变控件位置。
- 间距采用 4/8/12/16/24/32，圆角 6/10，正文网页默认 14–16px；重要读数使用等宽数字。
- 图标先使用可辨认的武器轮廓，并配中文名称；不以复杂火焰动画或透明纹理降低可读性。
- 正文对比度至少 4.5:1、控件/焦点至少 3:1；状态同时用文字/形状，支持减少动效及高对比主题。
- 网页全部交互支持键盘、清晰焦点及标签；弹出层管理焦点并可 Esc 关闭，状态播报不逐帧轰炸读屏。
- 在 390/768/1365/1920 宽度及 200% 缩放检查溢出；常用点击区域以 44px 为目标，表格窄屏转可读卡片。
- Canvas 预览提供动作名、进度和控制按钮的文本替代；动效暂停后不妨碍设置和退出操作。

## 10. 分阶段交付与验收

| 阶段 | 产物 | 验收 |
| --- | --- | --- |
| U0 信息与协议 | 页面流程、状态字典、配置继承和消息契约、设计 token | 与原生实际字段逐项对照，未实现能力明确列出 |
| U1 重点体验原型 | 莱万汀太刀/提夫罗斯弓页面和 HUD 可交互原型 | 初次进入、改键、试听、演示、停止完整可走通 |
| U2 通用模式整合 | 各支持模式、角色/武器矩阵、预设和状态反馈 | 共享组件不丢掉枪盾/弓等特有状态，错误和离线流程齐全 |
| U3 宿主接入 | EML 状态同步、配置迁移、原生 HUD 生命周期 | 真实离线宿主验证请求/回报、重连、停止和配置恢复 |
| U4 成品收敛 | 响应式、可访问性、主题、帮助、支持清单 | 浏览器自动检查及必要宿主/游戏抽验通过，遗留限制可见 |

- 角色、武器、材质和动作预览优先使用 BE 离线导出材料制作；不以进游戏抓取作为每轮 UI 迭代前置条件。
- 浏览器验证覆盖首次进入、两个重点组合、键位冲突、预设导入/覆盖、试听停止、未连接和失败恢复；保留截图与实际结果。
- 原生 HUD 验证 DPI、多显示器、窗口/全屏切换、缩放、焦点、点击穿透、布局编辑和关闭清理；模拟状态测试不能代替窗口行为验证。
- 最终进行必要的实际宿主/游戏抽验，核对遮挡、输入占用和显示对象；离线模型通过、浏览器通过、实机通过分别记录。
- 成品完成条件：承诺支持的角色/武器组合有可发现入口和准确状态，两重点组合流程完整，所有失败路径可退出，配置重启后可恢复。
